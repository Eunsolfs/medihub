# 手机端使用与安装（PWA）

MediHub 的站点支持**安装到手机桌面**：用安卓 Chrome 打开站点后，可以把它「装」成一个独立图标，
点开后全屏运行、没有地址栏，看起来和普通 App 几乎一样。这就是 **PWA（Progressive Web App）**。

本轮先做 PWA，不做原生 App，原因与后续路线见 §7、§8。

> 服务端**不需要额外组件**：PWA 就是同一个站点 + 一个 `manifest` + 一个 Service Worker，
> 都由 `apps/server` 托管。你只需要确认站点是 **HTTPS**（§5.1）。

## 1. 这是什么、不是什么

|                           | 说明                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| ✅ **是什么**             | 同一个网站 + 一层「安装」外壳。桌面有独立图标，启动后 `standalone` 全屏运行，不显示浏览器地址栏；不经过应用商店审核 |
| ✅ **技术形态**           | Web 应用：页面、交互、上传下载全部走浏览器内核（Chrome / WebView）                                                  |
| ❌ **不是什么**           | 不是原生 App：没有独立安装包（APK）、没有后台进程、没有系统级推送、不能离线写入                                     |
| ❌ **和「原生能力」无关** | 电子签名、UKey/读卡器、系统级文件关联、深度相机参数控制这类能力，PWA 都做不到（见 §4）                              |

它由站点的三个静态文件支撑（都随前端产物发布，可在浏览器里直接访问到）：

| 文件                    | 作用                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/manifest.webmanifest` | 应用名（`医档通 MediHub` / 短名 `医档通`）、`display: standalone`、`orientation: portrait`（竖屏）、`theme_color` `#0f766e`、`/icons/` 下的 192/512/maskable/apple-touch 图标 |
| `/sw.js`                | Service Worker：预缓存应用外壳（`medihub-shell-v1`），**不缓存** `/api/` 与 `/rpc`（避免串号/过期数据）                                                                       |
| `/sw-register.js`       | 注册上面的 Service Worker。**只在非 `localhost` 的页面注册**（避免开发时的缓存干扰 HMR）                                                                                      |
| `/offline.html`         | 断网或服务不可达时，导航请求回落到这个离线页                                                                                                                                  |

`index.html` 里已经带好 `<link rel="manifest">`、`<meta name="theme-color">`、iOS 的
`apple-touch-icon` / `apple-mobile-web-app-title`（标题 `医档通`），所以不需要你在服务器上改模板。

一句话：**它解决的是「医生在病房用手机快速拍照上传 + 查看」，不是「替代一个原生临床 App」。**

## 2. 安装到安卓桌面

### 2.1 前置

- 手机：Android + **Chrome**（或同内核浏览器：Edge、部分国产浏览器的「极速模式」）；
- 站点必须是 **HTTPS**（§5.1），且证书有效（不能是「继续访问」的自签证书）；
- 已用科室账号登录过一次（安装后打开时通常仍是登录态；换账号见 §9.6）。

服务端三件套能正常返回（在任意一台机器上验）：

```bash
for p in /manifest.webmanifest /sw-register.js /sw.js /icons/icon-192.png; do
  printf '%-24s ' "$p"
  curl -s -o /dev/null -w '%{http_code} %{content_type}\n' "https://medihub.summerecho.cn$p"
done
# 期望：/manifest.webmanifest → 200 application/manifest+json（或 application/json）
#       /sw.js              → 200 text/javascript 或 application/javascript
#       /icons/icon-192.png → 200 image/png
```

任意一个 404，就说明当前部署的版本不含 PWA 资源（升级到包含本轮改动的版本即可）；
`content_type` 不对（比如 manifest 被当成 `text/plain`）也会导致安装入口不出现。

### 2.2 两种入口

**入口 A：浏览器菜单**

1. Chrome 打开 `https://medihub.summerecho.cn` 并登录；
2. 点右上角 **⋮** → **「安装应用」**（部分版本显示为 **「添加到主屏幕」**）；
3. 弹出确认框 → 点「安装」；
4. 桌面出现 MediHub 图标，点开即为全屏。

**入口 B：页面内的安装提示**

站点在满足安装条件时（Chrome 触发 `beforeinstallprompt`），**页面底部**会出现一条提示：
标题「**安装到手机桌面**」，右侧一个「**安装**」按钮。点「安装」直接走系统安装流程，比翻菜单快。

> ⚠️ 这条提示**关掉一次就不再出现**（偏好记在浏览器的 `localStorage` 键
> `medihub:install-dismissed`）。关了以后还想装，用入口 A，或先清掉该站点的站点数据。

> 如果两个入口都没出现，先按 [§10.1](#101-安装入口自检清单) 的自检清单排查。

### 2.3 确认装好了

| 检查         | 期望                                                       |
| ------------ | ---------------------------------------------------------- |
| 桌面图标     | 有独立图标（不是 Chrome 的快捷方式角标）                   |
| 打开后的界面 | **没有地址栏**、没有浏览器标签页，状态栏下方直接是应用界面 |
| 最近任务里   | 显示为独立应用卡片，而不是「Chrome 的一个标签页」          |
| 卸载         | 长按图标即可卸载（和普通 App 一样）                        |

## 3. 手机上能做什么

| 能力                | 说明                                                                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **拍照上传**        | 页面上的「**拍照上传**」按钮（患者详情 / 资料库）在手机上直接唤起**后置相机**（`capture="environment"`，`accept="image/*,video/*"`）；卡片电脑上点同一个按钮会退化成选文件 |
| **录像上传**        | 同上，选视频时直接调起系统录像；大视频受配额与网络限制（§3.1）                                                                                                             |
| **从相册选**        | 也可以走系统文件/相册选择，批量挑图                                                                                                                                        |
| **预览查看**        | 图片缩放、视频播放（Range 流式）、PDF、docx/xlsx 预览、Markdown/文本                                                                                                       |
| **Office 在线编辑** | 配置了 OnlyOffice 时可以打开文档（**移动端编辑能力取决于 OnlyOffice 版本**，社区版没有移动端 Web 编辑器，见 [ONLYOFFICE.md](./ONLYOFFICE.md)）                             |
| **归档片下载**      | 只有 `root` / `dept_admin` 能下（见 [ARCHIVE.md §7](./ARCHIVE.md#7-大文件与分片下载)）                                                                                     |
| **科室切换**        | `root` 顶部的科室下拉在手机端同样可用                                                                                                                                      |

### 3.1 上传大文件前先看这三条

1. **单文件上限**：默认 256 MB（`UPLOAD_MAX_BYTES`）；手机 4K 视频很容易超过；
2. **配额**：科室/全站上限满了会直接报 413（[ARCHIVE.md §2.5](./ARCHIVE.md#25-排查-413--507)）；
3. **网络**：手机信号弱时上传**很可能中途失败**，且**不会自动续传**——需要重试，或改用「先传到电脑再上传」。

建议：拍完先看体积，超过 100 MB 的视频尽量在 Wi-Fi 下上传，并让屏幕保持常亮（部分系统切后台会掐断上传）。

## 4. 手机上不能做什么

| 限制                        | 影响                                                                                                                           | 规避                                                       |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| **没有后台任务**            | 切到别的 App 或锁屏，上传/下载可能被系统暂停或中断                                                                             | 上传时保持前台、屏幕常亮；重要的先传小文件                 |
| **没有系统推送**            | 收不到「审核/提醒/新消息」这类通知                                                                                             | 需要提醒时用院内 IM/短信；这是原生 App 才有的能力          |
| **不能离线写入**            | 断网时无法编辑、上传、保存；Service Worker 只缓存外壳，**不缓存 `/api/` 与 `/rpc`**，所以离线时看到的是 `/offline.html` 离线页 | 弱网下先拍照存在系统相册，回到 Wi-Fi 再上传                |
| **没有原生相机控制**        | 无法指定分辨率/曝光/对焦模式，也无法在 App 内做压缩                                                                            | 用系统相机拍好再选；或在服务端做压缩/转码（不属于本轮）    |
| **不能读 UKey / 签名板**    | 电子签名、CA 证书、读卡器类流程不可用                                                                                          | 这类流程走桌面端或专用终端                                 |
| **没有 APK / 应用商店分发** | 无法用 MDM 强制安装、无法离线分发安装包                                                                                        | 用「扫码打开站点 → 安装」的口径；需要 MDM 时请走原生（§8） |
| **弱网无重试队列**          | 上传失败需要人工重试，没有「稍后自动重传」                                                                                     | 见 §3.1；把大文件安排在 Wi-Fi 时段                         |

## 5. 部署要求

### 5.1 必须是 HTTPS（唯一硬要求）

浏览器只在**安全上下文**里才允许「安装」与 Service Worker：

| 访问方式                                    | 能否安装                                     |
| ------------------------------------------- | -------------------------------------------- |
| `https://medihub.summerecho.cn`             | ✅                                           |
| `http://medihub.summerecho.cn`              | ❌（不会有安装入口）                         |
| `http://localhost` / `http://127.0.0.1`     | ✅（浏览器把本机当安全上下文，仅本地调试用） |
| `https://` + 自签证书（有「继续访问」警告） | ❌ 通常会失败                                |

所以手机端上线前，先按 [DEPLOY-1PANEL.md §10](./DEPLOY-1PANEL.md#10-https-与强制跳转) 把证书配好，
并确认 HTTP 已 301 到 HTTPS。**内网 IP + http 的场景装不上，这是浏览器的规则，不是站点的问题。**

### 5.2 反向代理

站点与 API 同源、共存一个端口，反代不需要为 PWA 单独加规则。只需要确认两件事：

- `client_max_body_size` 够大（手机视频！），见 [DEPLOY-1PANEL.md §9](./DEPLOY-1PANEL.md#9-nginx-反向代理)；
- `proxy_read_timeout` 不要太短（大文件上传/下载），同上。

### 5.3 不需要的东西

- 不需要应用商店账号、不需要代码签名证书、不需要 APK；
- 不需要额外的服务端进程（PWA 静态资源由 `apps/server` 直接托管）；
- 升级站点后，用户下次打开自动是新版本（受缓存策略影响，见 §9.5）。

## 6. iOS 的差异

iPhone / iPad 也能「添加到主屏幕」，但能力比安卓 Chrome 少：

| 项               | Android + Chrome             | iOS + Safari                                            |
| ---------------- | ---------------------------- | ------------------------------------------------------- |
| 安装入口         | 菜单「安装应用」/ 页面提示条 | **分享按钮 → 「添加到主屏幕」**（没有「安装应用」字样） |
| 全屏运行         | ✅                           | ✅（从主屏图标启动时）                                  |
| 拍照/录像上传    | ✅                           | ✅（`capture` 支持，行为和系统相机一致）                |
| 文件选择         | 系统文件选择器               | 系统「照片图库 / 文件」二选一                           |
| 后台/推送        | ❌                           | ❌（Web Push 在 iOS 上限制多，本项目未使用）            |
| 缓存/离线行为    | 由 Service Worker 控制       | 更保守，更新更慢，清缓存路径不同                        |
| 长视频上传稳定性 | 一般                         | 更差（切后台容易中断）                                  |

结论：**iOS 能用，但建议只用来「看」和「拍小文件」**；大体量上传用电脑。
安卓是主推平台。

## 7. 为什么先做 PWA

| 维度      | PWA（本轮）                           | 原生 App（Expo / React Native、Electron/Tauri 壳） |
| --------- | ------------------------------------- | -------------------------------------------------- |
| 安装包    | **没有**，打开网址即可装              | 需要打包、签名、分发                               |
| 更新      | **随站点发布**，用户下次打开就是新版  | 要走应用商店审核 / 内部分发推送                    |
| 维护成本  | 一套代码（现有 SPA）                  | 多一套工程 + 双端适配 + 发版流水线                 |
| 审核/合规 | 不经过应用商店                        | 医疗类应用可能涉及隐私政策、资质材料               |
| 原生能力  | 相机拍照/录像、文件、剪贴板等基础能力 | 完整：后台任务、推送、生物识别、UKey、深度相机参数 |
| 离线      | 只能缓存只读页面                      | 完整离线写入                                       |
| 适合      | 病房里「拍完即传」、查资料、看时间线  | 需要离线、推送、签名、MDM 强管控的场景             |

判断标准很简单：

- **只是「用手机拍照上传 + 查看」** → PWA 足够，别上原生；
- **出现下面任一条** → 才值得考虑原生：
  1. 必须**离线**录入（手术室/地下室无网）；
  2. 必须**推送**（会诊提醒、审核通知）；
  3. 必须接**硬件**（UKey、签名板、读卡器、专用相机）；
  4. 需要 **MDM 统一分发/强管控**或应用商店上架；
  5. 需要**后台**长任务（批量转码、自动同步）。

原生要准备的东西（不是写代码就完了）：**应用签名证书**（安卓 keystore / iOS 描述文件）、
**分发渠道**（应用商店账号、企业内部分发、MDM）、**隐私合规材料**、**版本升级流程**、
以及长期的**双端维护人力**。

## 8. 后续选项：打原生壳

> ⚠️ **本轮未实现**。下面只是把「以后要走原生时怎么起步」写清楚，命令仅作参考，
> 不要当作现在就能用的功能。

### 8.1 移动端壳（Expo / React Native）

用 VibeStart 生成一个 Expo 工程，把现有 SPA 的接口（`/rpc` + `/api`）直接复用，先做一个
「容器 + 原生相机 + 本地队列」的壳，界面仍可大量复用 Web 组件思路：

```bash
# 示例：VibeStart 校验过的组合里取 desktop=electron、mobile=expo 的一套
# （实际生成时会按向导调整；本轮未执行）
npx --yes vibestart-cli@0.1.1 create medihub-mobile \
  --toolchain vite-plus --frontend react --framework spa --router tanstack-router \
  --backend hono --api orpc --database postgres --orm drizzle --auth better-auth \
  --ui shadcn --desktop electron --mobile expo --runtime node \
  --deployment none --testing playwright
```

要点：

- 壳里的「上传」应带**本地队列 + 断点重试**，这是原生相对 PWA 的最大价值；
- 登录复用同一套 Cookie/会话（或改为 token），注意与 Web 端的会话策略保持一致；
- 先做**只读 + 拍照上传**两个功能，别一开始就复刻整个站点。

### 8.2 桌面壳（Electron）

同一套 Web 站点也可以套桌面壳，用于「科室固定工位 + 离线查看归档包」：

```bash
# 示例（本轮未执行）：desktop=electron
npx --yes vibestart-cli@0.1.1 create medihub-desktop \
  --toolchain vite-plus --frontend react --framework spa --router tanstack-router \
  --backend hono --api orpc --database postgres --orm drizzle --auth better-auth \
  --ui shadcn --desktop electron --mobile expo --runtime node \
  --deployment none --testing playwright
```

> VibeStart 目前提供的是 **Electron** 桌面壳；想用 **Tauri** 需要自己初始化
> （`npm create tauri-app@latest`）再接入站点地址或本地静态资源，它不在 VibeStart 的可选组合里。

### 8.3 什么顺序做

1. 先跑稳 PWA（本轮）——覆盖 80% 的「拍照上传 + 查看」需求；
2. 归档量上来后，做**桌面壳**看归档包（最省事、收益明确，见 [ARCHIVE.md §6](./ARCHIVE.md#6-桌面端查看方案)）；
3. 真出现「离线/推送/硬件」需求，再做移动原生壳。

## 9. 常见问题

### 9.1 为什么没有出现安装入口

按顺序自查（F12 需要在电脑上开同一站点，或用手机上的远程调试）：

1. **是不是 HTTPS**？地址栏有没有「不安全」标记；`http://` 一定没有安装入口；
2. **证书是否受信**？自签证书、域名不匹配、过期，都会让浏览器进入「非安全」状态；
3. 打开 **F12 → Application → Manifest**：
   - 看不到 manifest → 站点没有输出（说明当前构建/版本不含 PWA 资源，确认升级到包含本轮改动的版本）；
   - manifest 有报错（图标 404、`start_url` 不可达、`name` 缺失）→ 按提示修，图标必须能 200 访问；
4. **Application → Service Workers**：没有注册或状态是 `error` → 看 Console 的报错；
5. 安卓 Chrome 需要**至少访问一次**站点、且停留几秒，才会判定「可安装」；
6. 在**隐私/无痕**窗口里不会出现安装入口；
7. **页面底部提示条是不是被关过了**？关过一次就不再弹（`localStorage` 键 `medihub:install-dismissed`），
   清掉该站点数据或直接用 Chrome 菜单里的「安装应用」；
8. **是不是用 `localhost` 打开**？`/sw-register.js` 在 `localhost` 上**故意不注册** Service Worker
   （避免开发时缓存干扰），所以本机调试看不到完整的安装链路，请用域名 + HTTPS 验证。

### 9.2 装完打开还是带地址栏

说明打开的是「浏览器标签页」而不是安装后的应用：回桌面**点新图标**启动；
若图标本身就是 Chrome 的快捷方式，删掉重装（长按 → 卸载，再走 §2.2）。

### 9.3 图标是空白/默认字母

manifest 里登记的是 `/icons/` 下的四个文件，逐个确认能 200 访问：

```bash
for icon in icon-192.png icon-512.png icon-maskable-512.png apple-touch-icon.png; do
  printf '%-24s ' "$icon"
  curl -s -o /dev/null -w '%{http_code} %{content_type}\n' \
    "https://medihub.summerecho.cn/icons/$icon"
done
```

期望全部 `200 image/png`。404 通常是前端产物没构建/没复制到 `dist/public`（见
[DEPLOY-1PANEL.md §7.1](./DEPLOY-1PANEL.md#71-spa-静态产物由构建自动复制)）；
`content_type` 是 `text/html` 说明被 SPA 回落接管了（路径写错）。

装完图标仍不更新：桌面图标是**安装时缓存**的，卸载重装才会刷新。

### 9.4 上传到一半失败

手机端最常见的三类原因：

1. **网络切换**（Wi-Fi ↔ 4G）导致连接重置 → 重试，或换稳定 Wi-Fi；
2. **文件太大**（超过 256 MB 或配额）→ 先在电脑上压缩/拆分，或让管理员调大上限；
3. **切后台/锁屏被系统挂起** → 保持前台、屏幕常亮再传。

判断是网络还是服务端：重试后如果立刻报错并带服务端文案（如「科室存储空间不足…」），
就是配额/磁盘问题（[ARCHIVE.md §2.5](./ARCHIVE.md#25-排查-413--507)）；如果是「网络错误/一直转圈」，就是链路问题。

### 9.5 站点更新了，手机上还是旧界面

PWA 会缓存静态资源以加速启动，刷新策略因浏览器而异：

- 先在应用内**下拉刷新/退出重进**（Service Worker 装好即 `skipWaiting` 接管，页面资源是
  「先用缓存、后台再更新」，所以多数情况下退出重进一次就够）；
- 仍不更新：关掉应用 → 系统设置里清除该应用/浏览器缓存 → 重开；
- 排查时可看 F12 → **Application → Service Workers**（当前 SW 是否 `activated`）与
  **Cache Storage**（缓存名 `medihub-shell-v1`；删掉它等于清空离线外壳）；
- 长期：这类「更新延迟」是 PWA 的固有特性，发版后建议在群里提示「退出重进一次」。

> 顺带说清一件事：Service Worker **故意不缓存 `/api/` 与 `/rpc`**，所以你不会看到「换了账号
> 还显示上一个账号的数据」；代价是**离线时看不到任何业务数据**，只能看到 `offline.html` 离线页。

### 9.6 一台手机要切多个科室账号

PWA 与浏览器**共用同一份会话**：在应用里退出登录再登另一个账号即可。
`root` 要切换「查看哪个科室」，用页面顶部的科室下拉（不是重新登录），见
[DEPLOY-1PANEL.md §17](./DEPLOY-1PANEL.md#17-科室作用域x-org-scope运维须知)。

### 9.7 能装在平板/电脑上吗

可以：Chrome/Edge 的桌面版也支持「安装」，效果是一个独立窗口。平板（安卓/鸿蒙）同理，
横屏体验接近桌面。这与 [ARCHIVE.md §6](./ARCHIVE.md#6-桌面端查看方案) 里说的「浏览器直接打开
归档包」不冲突，两者用途不同。

## 10. 附录

### 10.1 安装入口自检清单

| 检查项         | 通过标准                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 协议           | 地址栏是 `https://` 且无「不安全」提示                                                                                                                                    |
| manifest       | `curl -s https://<域名>/manifest.webmanifest` 返回 200 且是 JSON；F12 → Application → Manifest 能看到 `医档通 MediHub`、`standalone`、四个图标                            |
| 图标           | `/icons/icon-192.png`、`icon-512.png`、`icon-maskable-512.png`、`apple-touch-icon.png` 全部 200 `image/png`                                                               |
| Service Worker | Application → Service Workers 里状态 `activated` 或 `waiting`，无 error；`/sw.js` 与 `/sw-register.js` 均返回 200；**用域名访问而不是 localhost**（localhost 故意不注册） |
| 离线壳         | 断网后打开站点能看到离线页（来自 `/offline.html`），而不是浏览器的「无法连接」                                                                                            |
| 页面           | 至少完整加载过一次首页（能看到登录页/工作台）                                                                                                                             |
| 浏览器         | 安卓 Chrome/Edge 正式版；不是无痕模式；不是「桌面版网站」模式                                                                                                             |
| 系统           | Android 7+ 更稳；过老的 WebView 可能不支持                                                                                                                                |

### 10.2 一页速查

```text
装：Chrome 打开 https://<域名> → 登录 → ⋮ →「安装应用」/ 页面底部提示
验：桌面图标点开 → 无地址栏 → 最近任务里是独立应用
拍：进入患者/资料库 → 上传 → 相机拍照或录像 → 上传（保持前台）
查：时间线/资料库浏览；PDF/图片/视频预览
换账号：应用内退出 → 重新登录
换科室（root）：页面顶部「科室」下拉
更新：退出重进；必要时清缓存
```
